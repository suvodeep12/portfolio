# Portfolio workspace

- Stay in planning until the user approves the design. Ask before assuming intent, content, or assets.
- Prefer CLI tools over MCP when both can do the job.
- Use the simplest working solution: reuse existing patterns, prefer native features, and avoid unneeded dependencies.
- Keep portfolio content factual. Do not invent project details, metrics, testimonials, images, or links. Label unfinished work clearly.
- Version one uses hand-written Markdown project entries. GitHub metadata sync is a later option.
- Keep the first release to a homepage, project detail pages, real demo or source links, and contact links. Add richer portfolio interactions only after the project collection needs them.
- Before UI work, establish a clear design direction and apply the anti-slop filter during planning and implementation.
- Before claiming completion, run the site and check console errors, keyboard use, responsive layouts, and every interactive element.
